# 接口与数据一致性

## 身份与授权

PC和工程师沿用平台账户及Bearer会话；客户通过邀请码激活后使用独立客户会话，相关接口携带h5-token。两种会话不能互相替代。客户会话失效码10007与平台401/403分别处理。

菜单、路由和按钮反映可用能力，接口仍在后端校验权限和数据归属。部门、本人、客户、工程师及启用租户的数据范围应贯穿列表、详情、写操作和文件访问。

## 请求与响应

业务接口复用平台R响应模型，HTTP状态和业务错误语义分别表达。前端请求层集中处理会话、错误提示和失效跳转，页面不另建一套身份逻辑。

业务ID按字符串传递，避免JavaScript整数精度损失；金额使用后端定点计算规则。输入校验、空值处理与状态检查由所属业务服务完成，页面校验不能代替服务端约束。

## 状态、事务与幂等

服务层负责状态转换及关联记录的事务边界。并发和重试场景沿用现有幂等机制，避免同一业务动作重复产生库存、应收或实收。失败处理必须与实际事务结果一致。

库存只能由进销存单据服务变更，运维服务调用其业务能力。结算产生应收，收款产生实收；两者不可混同。

## 文件与签署

附件元数据和文件正文通过所属记录关联，预览、下载、回收与签署仍受身份和业务归属限制。文件格式、摘要和签署结果属于服务端校验责任，不能仅依赖扩展名或页面状态。

密钥、签署材料和真实环境配置独立持久化，不进入前端资源或源码分发内容。安全实现沿用SM2/SM3/SM4及既有协议标识，不随产品命名调整。
