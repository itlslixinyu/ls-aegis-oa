# EOMS 原生 Android 双端工作流

本文是新增「客户服务 Android」与「维修工程师 Android」的产品和工程基线。它规定如何从现有平台能力逐步交付原生应用，不表示 Android 工程或 APK 已经实现。

## 1. 当前边界与目标

- 后端继续由 `ls-aegis-server/ls-aegis-boot` 统一启动；维修业务仍归 EOMS，不新增 Android 专属业务服务、第二套管理后台或独立部署栈。
- `ls-aegis-h5` 已提供客户和工程师流程，是需求、接口和异常行为的现有参考；新 Android 客户端与工程师端是两个独立可安装应用。
- 推荐以 Kotlin + Jetpack Compose 构建原生界面，并在单一 Android Gradle 工程中组织 `customer-app`、`engineer-app` 和可复用 `core` 模块。开始编码前核对仓库/构建机兼容性，锁定 Gradle、AGP、Kotlin、JDK、compileSdk 与 minSdk；不在本计划中臆定版本。
- 共享模块仅放网络传输、统一响应解析、文件上传、加密适配、设计基础和通用组件。客户与工程师的会话、数据模型、路由和导航分别隔离，避免角色权限因共享状态串用。

## 2. 用户角色与端到端流程

### 客户端

1. 客户获得管理员在 PC「进销存 → 往来单位」签发的 8 位数字一次性激活/重置码。
2. 首次激活时输入邀请码、自己创建的全局唯一用户名和密码，并完成 EOMS 图形验证码；密码按平台 SM2 传输协议加密，后端以平台 `PasswordEncoder` 存储摘要。既有账户可用管理员重新签发的邀请码重置密码，用户名保持不变。
3. 后续直接使用用户名和密码登录（带图形验证码），调用 `POST /eoms/h5/auth/password` 换取现有客户 `h5-token`。8 位数字访问码十分钟内有效、只能使用一次、Redis 仅存摘要；激活接口每个 IP 每分钟最多 5 次请求。登录名不使用手机号或仅客户编号，避免没有短信验证和租户编号冲突的问题。
4. 会话安全保存 `h5-token`，后续请求按现有后端约定携带；退出时调用 `POST /eoms/h5/auth/logout` 并清除本地凭据。
5. 在线报修：选择故障类型、填写联系人/电话/故障描述/地址，按需选取现场照片并上传；提交成功后展示报修编号。
6. 我的报修：分页浏览本人记录，进入详情查看报修、工单进度、工程师维修记录和附件；客户确认仅在服务端允许的状态显示并调用确认接口。
7. 个人中心查看当前客户资料、退出登录。会话过期时回到账号登录页并保留可恢复的未提交表单，不缓存可识别附件到公开目录。

客户接口基线见 `ls-aegis-h5/src/api/customer.js` 与 `H5AuthController`、`H5RepairController`。账户只由具备业务权限的管理员通过邀请码建立绑定；不得开放客户编号/手机号直接注册、短信找回或绕过客户绑定的公共账号注册。

### 工程师端

1. 使用平台工程师账号登录，遵循 `/auth/login` 的平台认证、客户端标识、验证码/国密字段要求；取得用户信息并核验服务端权限。工程师不使用客户 `h5-token`。
2. 我的任务按待处理、进行中、已完成筛选；只显示服务端授权给当前工程师的任务。
3. 打开任务详情查看地点、客户报修、历史维修记录和附件；可联系客户、启动导航（由用户主动触发）。
4. 接单或开始维修；开始/结束等位置字段遵循权限说明并按需征求系统定位授权。定位拒绝时允许业务规定的手工流程，不能伪造坐标。
5. 维修记录填写处理内容、用料/工时等现有业务字段，按需上传维修中/完工照片；提交记录、完工并回看最终状态。
6. 个人中心查看平台用户信息并退出平台会话；会话失效/撤销时清除本地令牌并回登录页。

工程师 API 基线见 `ls-aegis-h5/src/api/auth.js`、`engineer.js` 及 `EngineerController`。动作接口以服务端状态机和权限为准，按钮显隐不能替代鉴权。

### 后台与财务后续闭环

Android 端提交的工单仍进入既有 PC EOMS 派单、维修材料/记录、结算确认链路。结算确认经 PSI 维修出库生成应收；只有实际收款才形成实收。客户端不自行记库存、结算、应收或实收。后台人员分派、财务、库存等本轮 Android UI 不属于两个移动应用的职责。

## 3. 应用与工程结构建议

```text
android/
  settings.gradle.kts
  build.gradle.kts
  gradle/libs.versions.toml
  core/network/       # API client、R 响应、超时、错误映射
  core/security/      # 平台加密适配、凭据存储、会话隔离
  core/ui/            # 主题、通用控件、无障碍基础
  core/files/         # 图片选择、压缩、上传进度与失败恢复
  customer-app/       # 客户应用入口、导航、客户会话
  engineer-app/       # 工程师应用入口、导航、平台会话
```

建议采用分层边界：Compose UI → ViewModel/用例 → repository → API。接口 DTO 与展示模型分开；Snowflake/业务 ID 按字符串解析和传递，金额使用十进制定点类型，不转浮点；分页、`R.success/code`、空值和服务端错误按当前项目规范处理。

不同应用使用不同 applicationId、应用名、图标、启动入口和凭据命名空间。开发/测试/生产 API 地址走构建变体或安全配置，生产包不包含本地明文密钥、测试地址和调试开关。

## 4. 身份、数据和设备安全

- 客户端只保存短期 EOMS 客户会话；工程师端只保存平台登录会话。登出、过期、撤销、切换账号清理对应会话及内存中的私有数据。
- 使用 Android Keystore 加密保护的存储封装令牌；不写日志、不放备份、不通过深链/剪贴板/崩溃上报暴露令牌。
- SM2 登录/字段加密复用现有平台协议实现；先对照 `ls-aegis-h5/src/utils/encrypt.js` 与后端登录链做跨端向量验证，不得自行降级到明文或另造协议。密钥/公钥获取、轮换和失败提示来自服务端契约。
- 每个详情、附件下载、上传和动作都依赖服务端身份/数据范围校验。客户端的列表过滤、路由守卫和隐藏控件不是授权边界。
- 照片仅在必要时申请相机、相册、定位权限；说明用途。上传保留后端水印、归属绑定和文件访问检查；本地临时文件使用私有目录并在完成/退出后清理。
- 离线模式第一阶段只允许草稿/只读缓存。禁止离线执行接单、开工、完工、客户确认、结算等状态变更；恢复网络后不得自动重放不可幂等写操作。

## 5. 实施阶段与门禁

| 阶段 | 工作 | 交付物 | 进入下一阶段条件 |
|---|---|---|---|
| A 需求冻结 | 用现有 H5、Controller、Service、状态机逐项核对；确认系统版本支持范围、隐私文案、应用包名、推送需求与发布渠道 | 页面/动作清单、角色权限表、字段与错误态清单、未决问题 | 用户确认影响产品范围的未决项；接口无猜测字段 |
| B 契约与原型 | 记录接口方法、路径、请求/响应、错误码、会话头、分页、文件上传、状态前置条件；审核客户/工程师导航原型 | API 契约表、关键页原型、状态流转图 | 与当前后端源码和 H5 一致；数据范围与敏感信息审核完成 |
| C 工程底座 | 创建 Gradle 工程、应用变体、core 模块、网络/响应解析、加密适配、会话存储、日志脱敏 | 可运行空壳、开发构建说明、协议向量记录 | 两个应用可构建；加密登录、令牌隔离和错误处理通过针对性验证 |
| D 客户端闭环 | 授权登录→提交报修→列表→详情→客户确认→退出 | customer-app、接口映射和人工验收记录 | `EOMS-ANDROID-C-01` 核心用例及越权/重试/过期用例完成 |
| E 工程师闭环 | 平台登录→任务列表/详情→接单→开工→记录/照片→完工→退出 | engineer-app、接口映射和人工验收记录 | `EOMS-ANDROID-E-01` 核心用例及抢单/非法状态/权限用例完成 |
| F 后台联调 | Android 报修进 PC 派单、工程师操作回显、结算生成 PSI 出库/应收、实际收款形成实收 | 跨端业务闭环证据与缺陷清单 | 关键 ID、状态、附件归属、库存和应收实收核对一致且重试无重复 |
| G 发布准备 | 设备/OS矩阵、签名与渠道配置、隐私与权限核验、崩溃/性能检查、版本和回滚方案 | 签名构建、发布检查单、运维说明 | 签名凭据安全保管；生产环境和商店资料由授权发布流程确认 |

## 6. 验收基线

| ID | 场景 | 必须检查 |
|---|---|---|
| EOMS-ANDROID-C-01 | 客户报修完整闭环 | 邀请码激活/重置、用户名密码登录、验证码错误/过期、口令错误锁定、字段校验、图片上传失败重试、本人数据范围、详情刷新、客户确认和重复提交 |
| EOMS-ANDROID-E-01 | 工程师维修闭环 | 平台登录/退出、权限不足、授权任务、并发接单、非法状态动作、照片归属、定位拒绝、网络中断及状态刷新 |
| EOMS-ANDROID-X-01 | 双端与 PC/财务联合 | 客户报修→PC 派单→工程师完工→客户确认→结算确认→PSI 出库/应收→实际收款；核对事务回滚、幂等与 ID 精度 |
| EOMS-ANDROID-SEC-01 | 会话与数据保护 | 跨应用令牌隔离、失效/撤销、跨客户/工程师越权、附件越权、日志/备份/深链泄露检查 |
| EOMS-ANDROID-UX-01 | 设备可用性 | 小屏、字体缩放、横竖屏、键盘遮挡、无障碍标签、弱网/超时/空列表/服务端错误态、相机/相册权限拒绝 |

实测结果保存在本地 `.local/android/<run-id>/`，不提交逐轮测试报告。源码审查、单元测试、模拟器流程、真机验证和后台财务联调分别标记；未执行项写 `NOT_RUN`，外部服务/身份缺失写 `BLOCKED`，不得以编译成功代替业务通过。

## 7. 需要产品/基础设施确定的事项

应用包名与品牌标识、最低支持 Android 版本、是否需要推送/深链/离线、工程师账号开通策略、客户访问码发放运营流程、地图 SDK 与定位合规策略、应用分发渠道、签名密钥托管和隐私政策尚需由项目决定。实现前通过 A 阶段记录决策；不得硬编码供应商密钥或默认开放权限。
