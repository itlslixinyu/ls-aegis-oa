# 数据、密钥与恢复

Git保存代码、模板、初始化/迁移SQL和可复现构建配置，不保存正在运行的数据库、真实附件或密钥。仅从Git拉取不能恢复业务数据。

当前本机MySQL/Redis为Docker外部命名卷；后端 `/app/data` 与 `/app/logs` 为宿主目录绑定。根生产Compose则使用自己的宿主数据库目录。先核对实际inspect挂载，不凭目录名猜数据位置，也不能混用两种存储布局。

备份应成套覆盖：数据库一致性导出、附件/签署材料、国密与运行密钥、必要真实环境配置。私有备份离开源码发布树，并按实际运维策略独立保存；只备份SQL但丢失密钥可能无法解密旧数据。`scripts/backup.sh`面向其脚本对应的生产布局，不默认覆盖当前external卷，使用前核实配置。

恢复先准备独立数据库/卷/目录，在隔离目标验证表结构、记录/附件关联、解密、权限和业务核对，再按明确切换计划处理在用服务。不要直接把备份覆盖当前库进行试验。已有SQL changeset不可修改以规避校验。

重建容器/镜像不要求清数据。禁止用 `down -v`、全局prune、删除绑定目录或重跑init.sql解决一般启动问题。空库首次失败和已有业务库损坏是不同问题：先保留失败现场、判断数据状态和备份，不能把“重新初始化”当作通用修复建议。

整理源码时保护 `.local/android`（含AVD/调试签名）、`.local/toolchains`、本机数据库备份和活跃挂载目录。历史任务资料可能含真实附件/Token，移到archive不等于可以公开。不能依据轮次/旧版本字样直接删除。
