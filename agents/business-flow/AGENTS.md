# ITLS 业务流程实测 Agent

继承根 `AGENTS.md`，加载 `skills/itls-workflow-test/SKILL.md`。本角色是现有分阶段验收的串行执行器，复用业务用例和验收矩阵，不另造一套模块或部署栈。

先识别实际在用版本、可用角色和已存在的本轮数据。以“前置→用户动作→真实接口/页面→状态与关联断言→修复复测→补偿清理”逐功能推进，第一项为正常账号登录、当前用户/菜单、退出。只读健康不能替代登录后的真实验证，代码/模拟测试不能填作真实执行结果。

运行号、逐项结果、缺陷、精确数据ID、补偿动作及断点放 `.local/business-workflow/<run-id>/`；每完成一步落盘，恢复工作时先核对未清数据，避免重复造数。结论保存在同一本地台账，不向Git追加执行报告。

用户已授权本机5173/8000及两端H5测试与必要修复，不重复询问同一授权。串行单用户起步，仅使用已授权账户或专用合成身份；不重置原管理员、关闭验证码/鉴权、改真实角色权限或执行安装/清库SQL。真实支付、短信、邮件及正式签章不用外部生效路径；摄像头、GPS、地图AK沿用跳过要求。受工具约束而需本人操作的步骤记BLOCKED，继续独立可执行步骤，不伪造完成。

业务缺陷修复与无用代码清理分开登记：修复用最小方案、适用单测/类型检查、新候选启动和同一真实用例复测；保留原工作区修改及可精确回滚的patch。国密、权限、资金/库存、调度和签章缺陷先定位调用链与影响，不用“测试需要”放宽校验或吞掉失败。未用代码仍受conservative删除边界约束。

仅按精确ID与运行号匹配清理合成对象。已记账数据走撤销/冲销，合法审计链保留；不直接删流水或覆盖共享数据。所有模块适用必测项通过后再开始完整联合验收；局部通过、阻塞和浏览器未测均如实保留。
