# 本地目录与新仓库整理

先读取根 `AGENTS.md`、[整理 Agent](../../agents/repo-organize/AGENTS.md)，执行时按[阶段工作流](references/workflow.md)推进。项目 Skills 继续放根 `skills/`，不假定原生工具能自动发现；由根规范显式路由。

## 范围判断

- 只要求建议或生成工作流时，交付方案、Agent、Skill 和只读盘点，不开始破坏性清理或发布。
- 要求执行整理时，先保存已有修改与运行基线，再按证据分类和小批次实施。
- 要求准备新仓库时，先形成可审阅的候选树；创建远端、提交、推送、打标签按用户实际授权执行。不要将过去对旧仓库的一次授权扩大到新仓库或历史改写。
- 拟定名称 `ls-aegis-oa`、展示版本「1.0」与原项目2.2.0历史分开记录；发布实施时统一新项目版本矩阵，保留技术基座名称、第三方依赖和不可变历史版本。

## 分类与证据

使用 `git status --short`、`git ls-files`、`rg --files` 和定向引用检索，区分 Git 跟踪、忽略的本机资料、构建产物和运行数据。扫描默认跳过数据卷、真实配置/密钥内容、SDK、AVD、node_modules、target、dist 和 Git 对象库；检查这些目录的用途与挂载关系即可。

每条候选记录 `source,target,category,evidence,action,risk,status,validation,rollback`：

| 类别 | 处理 |
|---|---|
| 当前源码与工程规范 | 保留；架构变更另立验证范围 |
| 当前有效文档 | 以实际行为重编到唯一权威位置，修正引用 |
| 历史资料 | 摘要当前仍有效的决策，登记原版本；脱敏后按发布方案归档，私有证据留本地 |
| 已证实的临时/重复产物 | 授权执行时可归档或清理；同名、旧版本字样不能独立作为删除依据 |
| 运行数据/密钥/活跃工具 | 保留原位并排除发布，不当作垃圾 |
| 证据不足或动态引用 | 标记待复核，追踪脚本/容器/路由/反射等实际使用 |

## 文档迁移约束

文档分层规则已生效：从 `Docs/README.md` 进入，现行主题按目录维护，执行结论写 `Docs/releases/maintenance.md`。`Docs/Reports-README.md` 兼容历史链接，原文在 `Docs/archive/legacy-reports.md`。再次迁移前仍须同步根规范、规则与相关Skill，不创建重复权威来源。

当前文档、历史报告、实际证据分别标记。每个功能只保留一个维护入口；源码附近必要的 SQL/迁移说明、Android 构建说明、许可和协议文档可就近保留并由总索引链接，不强行集中复制。

## 运行保护与校验

当前统一 Compose 项目为 `ls-aegis`，本机入口 5173/5174/5175/8000，兼容 25683/25684/25685/25682。MySQL/Redis 使用外部卷；`docker/data/`、`.local/` 的实际使用必须先核实，不能执行 `git clean -xfd`、`down -v` 或全局 prune 来整理目录。Android App 属于安装在设备上的入口，不能把 H5 启动冒充 App 启动。

文档改动检查链接、锚点、命令和索引；移动脚本/配置时检查 Docker COPY/context、Compose 路径、打包入口和忽略规则，运行受影响构建及启动冒烟。测试环境与在用数据分开，隔离栈使用独立卷和端口。只回退本批修改，不回退他人改动、数据库或真实业务数据。

工作清单放 `.local/repo-organize/<run-id>/`；正式结论按当前报告规则记录。保持中断可恢复，区分「拟定结构」「已迁移」「构建通过」「部署通过」「业务闭环通过」「已发布」。
