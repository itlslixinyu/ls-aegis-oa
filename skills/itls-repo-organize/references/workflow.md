# ls-aegis-oa 管理平台 1.0 整理工作流

本方案作用于现有仓库，不是复制所有本机文件上传 GitHub。以「干净源码仓库 + 可重建部署 + 独立持久化数据」为交付边界。当前只生成规范时，不自动开始以下移动、删除、改版或发布步骤。

## 阶段与退出条件

| 阶段 | 动作 | 可审阅产出 | 退出条件 |
|---|---|---|---|
| 0 基线锁定 | 核实 HEAD、远端、已有差异、真实根目录、Compose/端口、卷/挂载、AVD 与工具路径 | 基线和保护范围 | 已有修改可追溯；运行数据与源码已区分 |
| 1 全量目录盘点 | Git 跟踪清单 + 定向查看忽略目录元数据，按用途/引用/重复证据分类 | 文件台账、重复候选、待复核列表 | 每项有证据；没有以未跟踪或旧命名直接判无用 |
| 2 文档设计 | 确认现有业务范围，提取巨型报告中的现行说明，标记过时/相互矛盾/未验收内容 | 新目录和旧→新映射、规范迁移清单 | 每个主题唯一权威来源；历史结果不会被误读为当前验收 |
| 3 低风险整理 | 先重编/索引，再按批次迁移并修正引用，最后清理已核实冗余 | 每批 diff、变更清单及回退步骤 | 本批链接/命令检查通过；原有修改和运行目录未被覆盖 |
| 4 工程目录核对 | 审核构建、打包、Docker、SQL、Android、Agent/Skill 的入口和忽略规则 | 候选源码树、发布排除清单 | 一套权威部署入口；开发/生产/本机覆盖用途明确 |
| 5 名称与版本实施 | 明确新仓库和旧基座的命名边界，按授权同步新项目品牌及 1.0.0 版本矩阵 | 名称/版本对照、发行说明 | 不全局替换历史版本、第三方版本、Java 包或数据库迁移标识 |
| 6 验证与收尾 | 在隔离候选目录核对仅含拟发布文件，构建、隔离部署、执行适用回归 | 验证记录、剩余问题、迁移清单 | 必需检查真实通过；失败批次回退；未测项明确 |
| 7 新仓库交付 | 在已获发布授权时创建/使用目标远端，审阅暂存内容，正常提交/推送/打标签 | 新仓库地址、commit/tag、交付说明 | 远端内容核验一致，无凭据/数据/私有证据；旧仓库保留 |

先完成全部盘点再进入实质清理。中高风险项不自动删除；必要的行为重构单独验证，不能混进文档整理批次。

## 目标目录结构

保留当前有效源码目录名称，避免仅为视觉整齐影响 Maven、Vite、Docker 和 Android 构建：

```text
ls-aegis-oa/                 # 新仓库名；现有在用路径暂不搬迁
  README.md                 # 产品范围、快速启动、文档入口、版本
  VERSION                   # 发布阶段统一为已授权的新版本
  AGENTS.md
  ls-aegis-server/
  ls-aegis-web/
  ls-aegis-h5/
  android-demo/             # 如实标注 WebView 测试工程
  docker/
  docker-compose.yml        # 部署基础配置
  docker-compose.local.yml  # 已有本机数据的覆盖配置
  scripts/
  tests/
  agents/
  skills/
  rules/
  Docs/
    README.md               # 未来文档总索引
    guides/                 # 安装、开发、操作说明
    business/               # 已有模块与跨模块业务流程
    architecture/           # 分层、接口约定、权限、数据边界
    operations/             # 环境、部署、升级、备份恢复、监控
    testing/                # 测试标准、矩阵、已测与未测
    releases/               # 新版本变更与已执行验收结论
    archive/                # 经筛选脱敏的旧版历史说明
```

文档分层已实施：`Docs/Reports-README.md` 保留章节兼容锚点，原文在 `Docs/archive/legacy-reports.md`；现行说明由 `Docs/README.md` 索引。阶段2映射和批次证据保留于本机台账，新维护记录写 `Docs/releases/maintenance.md`。

业务说明按实际启用模块组织：平台账号/权限/组织、文件消息、PSI、报价、EOMS、签章和移动入口。已移除的代码生成/应用管理仅在历史变更里说明，不重新列为平台功能。OA 作为产品名称，不凭名称增加审批、人事等尚不存在的能力。

## 本地数据与 Git 边界

| 内容 | 本地处理 | 新仓库处理 |
|---|---|---|
| 源码、锁文件、构建入口、必要 Wrapper | 保留、验证引用 | 纳入 |
| 当前有效文档、Agent、Skill、规则 | 整理并维护索引 | 纳入 |
| 新装 init.sql、有效增量迁移 | 原位保留及验证 | 纳入，不能按文件日期清理 |
| 模板配置 | 保留必要说明 | 仅占位值，无真实密钥 |
| Docker 外部数据卷、附件、密钥/证书 | 原位保护；数据备份单独维护 | 不纳入 |
| .local 下 SDK/AVD/JAR/工具链 | 先查活跃进程和挂载；仍在用就保留 | 不纳入，记录重建方法 |
| 数据库导出、会话证据、真实日志 | 私有保留，按具体保留策略处理 | 不纳入；不能改个文件夹名称就公开 |
| node_modules、target、dist、APK/镜像包 | 可重建但先查是否运行依赖 | 不纳入源码树；安装包按独立发布流程处理 |
| .agents/.cursor 等残留 | 逐项确认 IDE 使用与根 skills/rules 是否重复 | 按证据处理，不按目录名直接删除 |
| 第三方许可、NOTICE、协议与必要内嵌文档 | 原位保留 | 保留合法和运行所需内容 |

移动前核对绝对路径落在目标工作区；活跃运行目录的外层重命名同样会破坏挂载，不得只检查目录内部。若需要把新仓库放到新的同级路径，先验证该路径写权限并以不含本机数据的候选源码树准备；不直接搬走当前运行根目录。

## 批次与验证

建议批次：文档索引/去重 → 已授权的文档迁移 → 临时文件整理 → 构建与部署入口 → 品牌和版本 → 候选发布。每批有独立 diff 和验证；普通提交与较大的小版本发布按照当前用户要求，不自动为每批打版本标签。

- 文档：本地链接/锚点、大小写、权威入口和命令路径；逐项说明与当前源码、运行环境是否吻合。
- 工程：后端 JDK 21/Maven、PC pnpm 9 类型检查/构建、客户/工程师 H5 分端构建；Android Wrapper 和两端 APK 构建按影响执行。
- 部署：Compose 安全解析（不输出插值后的凭据）、Docker 构建上下文、环境模板、路径与持久化规则。现有 Compose 数据核对与候选空库初始化分开，隔离栈不得使用当前外部卷、容器名或端口。
- 运行：重命名/路径变动影响运行时，执行对应启动与 HTTP 冒烟。纯文档批次无需无目的重启或全套业务写入。
- 业务：行为代码有变更才执行相应单元/集成及已授权业务回归；只读部署冒烟不能代替业务闭环。摄像头、真实 GPS 和地图 AK 继续保持用户指定跳过。
- 发布：扫描候选文件和实际拟推送历史，不展示秘密内容。确认 `.env`、数据、签名和私有备份未进入提交；新仓库是否保留旧历史由发布方案明确，不能默认通过删除历史解决。

当前阶段只交付工作流时，使用内容校验、引用核对和 Skill 校验即可，不为了生成 Markdown 重启平台或操作业务数据库。

## 命名和版本矩阵

阶段 5 同步核对根 README/VERSION、PC/H5 package 与锁文件根元数据、Maven/application 产品元数据、Compose 自有镜像标签、打包/安装脚本和发行说明。Android 调试工程的现有版本与未来平台版本单列，若发布方案统一则同步 versionName/versionCode；不宣称 WebView 包已完成原生应用验收。

不改第三方依赖版本、基座的法律/技术标识、已执行 changeset 内容或 ID、历史报告中的原版本。新项目 1.0.0 是一次明确的发布基线建立，不是对旧项目 2.2.0 文本进行全局替换。

## 验收交付

交付本地目录与发布树对照、文档总索引、保留/归档/删除/待复核台账、批次差异和回退方式、构建/运行/业务测试的分层结果、仍需处理事项。只有完成外部发布并核对后，才能写「已发布 ls-aegis-oa 1.0」。
