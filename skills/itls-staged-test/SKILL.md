# ITLS 分阶段测试

读根 AGENTS.md、本技能的 [验收矩阵](references/acceptance.md) 和 [国家标准依据](references/standards.md)。用户已授权在指定在用实例测试，范围授权持续有效，不逐项重复询问；缺少地址、身份或业务验收指标时只询问缺失信息。2026-11-05 已确认目标为本机 PC5173/API8000，H5默认5174/5175；其当前 dev profile 与公网生产不同，报告必须如实标注。

按矩阵顺序逐个模块执行。每模块完成适用的代码检查、真实接口、页面交互、角色权限、状态/金额/数量断言及清理复核后才记 PASS。无独立页面/接口的底座能力经实际调用方验证，不强造页面。基础依赖可提前就绪，共享资料来自同一平台，不虚构业务模块完全独立。全部必测模块通过后才执行联合测试；部署配置证明不适用的项目可记 N/A 并排除，缺前置的 BLOCKED/NOT_RUN 不能转 N/A。修复导致版本变化时重测影响模块与依赖链，联合结果只能对应同一最终版本。

## 在用实例执行与清理

使用专用测试账号、合成客户/商品/文件和唯一 ITLS-TEST-运行号；创建前记录现状，创建后立即登记实体 ID、关联 ID、归属与补偿动作。不要借用真实客户印章、证书或业务文件。初始默认串行单用户、只读基线；重复写/并发验证限定同一合成记录的一对请求，不进行无界压测或故障注入。出现真实数据变动、异常率升高、不可补偿副作用，停止新增写入，保留证据并处理补偿，不自动重试扩大影响。

用户已授权必要测试操作；对无法真正撤销的对外支付、正式签章、真实短信/邮件等，使用合成对象或无对外发送的路径。不能用“之后删记录”宣称撤回外部效力。不得重置原管理员密码、关闭在用验证码/审计、运行安装 SQL、直接删账务/库存流水或整体恢复数据库。

清理按依赖逆序通过业务 API 撤销、作废、冲销，再删可删除的合成草稿/附件。已记账业务通过补偿恢复净库存、余额、实收，保留合法审计链。按精确ID和运行号双重核对所有权；存在被真实业务引用或无法撤销项时不得强删，记残留原因与后续处置。清理后独立回查净增量、附件引用、缓存和待办，不以删除接口返回成功代替清理验收。

`run_business_flows.py` 是隔离夹具脚本，含建库/账号初始化/验证码调整，禁止改指向此在用实例。单测和构建继续在本地执行；在用实例测试另用经过检查的业务 API 用例，不运行迁移器或测试容器清理命令冒充业务数据清理。

## 证据与验收

每用例记录标准框架、需求、模块、版本、目标、账号角色、前置、步骤、预期、实际、证据、缺陷、重测及清理状态。状态使用 PASS/FAIL/BLOCKED/NOT_RUN；API、页面、代码审查、单测分别记录。没有运行过不能沿用旧的14组结果。门槛、P95/错误率/并发/资源上限是项目约定，未确定则非功能验收 BLOCKED，不编造“国家标准规定3秒/100并发”。

正式报告仅追加 Docs/releases/maintenance.md；含身份/证据的运行台账放忽略目录 .local，脱敏并保留足以复核的证据。标准框架对齐不等于国家标准认证或第三方测评通过。
