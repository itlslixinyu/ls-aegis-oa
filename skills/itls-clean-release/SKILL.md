# 品牌与干净初始化

读取根AGENTS及[实施角色](../../agents/clean-release/AGENTS.md)。运行基线、Android和SQL约定分别沿用itls-maintain、itls-android与rules/SQL规范.mdc。

1. 保存现有工作区差异、应用镜像、数据挂载和关键文件指纹。先核实唯一安装入口 `ls-aegis-server/sql/init.sql` 与空库/原卷两种部署语义。
2. 从现行公开SITE配置定位用户指定Logo，取得原文件并比对摘要；只将已指定品牌图片写入源码，不导出上传库、账号令牌或配置密钥。PC/H5默认资源和Android图标逐项核对，运行配置继续允许合法覆盖。
3. Android显示名修改不更换包名、签名或版本。欢迎区使用同一组件；长公司名用可测的自适应字号保持完整一行，不用省略号或裁切来冒充完整展示；过长时保留可读的单行横向浏览回退。服务中心小标题单独居中。
4. 对全新安装种子分类：表结构、管理员及所属根部门、菜单/权限/字典/必要配置和模板可保留；业务单据、客户商品、附件引用、通知公告、样例账号及私人背景不得携入。角色定义不等于额外用户。已有Liquibase changeset不改正文；需要的新安装差异采用明确的安装专用路径，不能让升级隐式清空生产库。
5. 仅在独立无网络、无宿主端口、无原有持久卷的临时MySQL验证；核对所有非白名单表为空、只有管理员用户、关联无悬空、外观指向仓库资源、SQL编码和完成标记。临时容器按创建所得ID清理，不能匹配名称批量删除。
6. 验证两端H5/PC受影响构建、AndroidAPK标签及设备页面。只有用户已授权更新运行环境时才替换相应应用服务，保留数据库、附件、密钥及App本地会话。设备安装被拒绝时交付APK并记录限制。
7. 必要现行说明同步Docs，执行清单、patch与报告保存 `.local/android/<run-id>/`。未获本轮授权不提交、推送或升版本。完成后在当前对话通知用户，不创建用于追踪本任务的定时自动化。
