# 校验与精确回滚

读根 `AGENTS.md` 和 `agents/code-cleanup/AGENTS.md`。输入运行号、LOW修复白名单、逐文件preimage及基线验证结果；阶段1只准备门禁，不修改业务。

## 修改前

确认Git HEAD、既有修改和本批路径/起止行，保存逐文件原字节与SHA256、计划diff、工具版本及已有失败。高风险/非白名单项拒绝进入批次。基线启动失败或关键工具不可用时记BLOCKED_FOR_CLEANUP，**不先改代码再等待环境**。

## 修改后逐批验证

1. 后端从父工程使用JDK21、Java17 release，执行受影响模块及依赖的compile/test；最终涉及后端时完成boot完整构建，不能用skipTests称单测通过。
2. PC先typecheck再生产build/模块图/资源门禁；H5涉及变更分别构建customer/engineer。仅沿用锁定依赖，不升级。核对生成类型及构建输入哈希。
3. 在原来可用且允许的隔离环境启动**本批候选**，使用项目真实健康/就绪入口与适用的service_smoke；设置启动期限，校验HTTP和平台业务返回。已运行的旧进程不证明新候选启动成功；401健康接口不当作健康成功，也不绕过认证。
4. 执行适用业务/权限/幂等联动，复用itls-business-test的唯一运行号与合成栈，清理仅限本轮标签与数据。浏览器/硬件未测写NOT_RUN，不能用静态或单测替代。

任一必需编译/测试/候选启动/联动失败、超时或无法执行，均不保留清理批次：先记录失败与本批postimage，再核对当前哈希仍等于postimage，逐文件恢复preimage。并行修改导致不匹配则停止覆盖、报告冲突；禁止整仓reset/clean/checkout。恢复后验证原哈希及工作区差异，清理本批进程/容器，不删除共享环境或原有数据。未知回滚不能写成功。

全部必需检查通过后保存结果矩阵、变更SHA256、逐项实际动作及限定路径patch（含before/after哈希）；回滚命令必须针对该白名单且可先预检。执行前无本批修改时不制造回滚或撤销既有提交。输出 `validation.json`、`changes.patch`、受控回滚说明及统一报告；日志/原字节只在忽略的运行号目录，不含密钥或真实数据。本Skill不单独授予提交/推送权限。
